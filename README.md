# TIMAntiRecall

作者 **Xiaofei**，插件域 `com.minis.timantirecall`。
目标 **TIM4.1.0 / build4.1.0.81 / com.tencent.tim / iOS16.5**。独立 TrollFools 注入 `.dylib`，不依赖越狱库、PreferenceLoader 或重打IPA。

## 本轮功能

基于用户已反馈有效的0.80/f6c3ef6，新增：

1. **重启保留撤回标记**：默认开启，最多4096条消息身份与首次拦截时间；不保存聊天文字、图片或语音副本。
2. **按聊天单独开关**：私聊、群聊按账号隔离；关闭后，此聊天后续撤回通知原样交给TIM处理，不再拦截。不会删除之前已经保留的消息，也不能找回关闭期间被TIM删除的消息。
3. **标记旁显示拦截时间**：可选在原标签旁显示 `已撤回 · HH:mm:ss`，默认仍是0.80的“已撤回”。重复通知保留首次时间。
4. **TIM内设置面板**：TIM设置页右上角“防撤回”；私聊/群聊详情页同样有入口，可管理当前聊天。
5. **气泡外侧双击复读**：设置页独立开关，默认关闭。对方消息右侧、自己消息左侧空白双击，发送纯文本、普通/市场表情、已下载的单张图片，以及包含正文与表情的整条引用回复（保留原引用目标及预览）。所有富元素重建为独立对象，不改原消息、不改编辑器草稿；图片走原生上传，使用临时隔离副本，原文件不动。仅普通私聊/群聊；图片须为 TIM 沙盒内完整本地资源且不超过24MB；闪照、未知/失效资源、未下载原图、红包、文件、卡片、图片混排回复及不支持的对象图不发送。多段文字与有明确目标的普通@消息使用原生元素重建并保留提及关系；链接、独立全员@、频道/角色提及仍不复读。单条普通视频使用TIM原生消息转发接口，以原消息ID发送到当前同一聊天；不复制/删除视频文件，不拼资源地址，失败不重试。视频准入及同源同目的接受由原生流程/服务端决定，可能保留原生转发显示或清晰度行为。接收图片可以使用TIM原生解析出的已有原图缓存，不要求消息填写sourcePath，也不自动下载或拿缩略图替代。TIM原生文字双击保留，接口调用不代表服务端送达。详见 [富消息复读](docs/rich-message-replay.md)。

普通消息行仍沿用0.80的NT当前Swift模型反射和传统消息转换身份桥。整行细红框包括头像/气泡，右下标签不抢触摸，滚动复用重新核对身份。原始撤回分类器与目标UUID保护不放宽。

## 安装和使用

1. TrollFools仅移除启用的本插件旧库（如0.80），旧 `TIMAutoRevoke31.dylib` 保持停用。
2. 注入新版独立动态库，完全退出并重开TIM。不卸载TIM、不覆盖IPA。
3. **TIM → 设置 → 右上“防撤回”**，管理总开关、重启保留、时间显示和按聊天开关。
4. 聊天右上详情页的“防撤回”可直接打开当前聊天设置。若身份尚未识别，先返回聊天查看普通消息；不根据昵称/头像/行号猜测聊天。
5. 关闭重启保留会先提示确认，再移除插件标记文件，本次进程的标记仍保留。移除动态库并重开TIM可停用插件。

## 数据与边界

标记和设置保存在 **TIM数据沙盒** `Library/Application Support/TIMAntiRecall/marks.plist`、`preferences.plist`。二进制plist原子写入、文件权限与iOS文件保护，仅本地、不联网，并请求排除备份；这不等于独立加密。损坏/不可读文件不静默覆盖，面板显示错误。详细实现、确切ABI和回归要求见 [recall-preferences.md](docs/recall-preferences.md)。

- 只保存本版本启用后实际拦截的新事件。0.80退出前的纯内存标记不能补回。
- 原消息若被TIM历史同步删除、媒体过期，标记不能恢复正文/附件。离线撤回、历史同步仍不保证。
- 持久化标记：每次成功拦截时，身份条目会在拦截 Hook 返回前写入并确认完成；设置和其他状态更新仍使用串行异步写入。若写盘失败，日志记为 `recall-mark-persist-failed`，仍保留本进程内拦截，但重启保护无法保证。上限4096条时淘汰最早记录。
- 未识别过的聊天可能要先打开才能出现在管理列表；私聊QQ号通过真实消息record的UID关联，不做账号换算猜测。身份无法确认时保持既有保护，不误用另一个聊天或账号的开关。
- 时间是本机插件首次拦截的时刻，不是服务器权威时间或原消息发送时间。
- 本人发起的私聊/群聊撤回原样交给 TIM，不新建插件标记；群聊按操作人而非消息作者判断。操作人或推送账号无法确认时也原样放行，因此这些未知格式不再保证防撤回。已能确认的本人旧标记不再恢复；群旧标记缺操作人时仅凭历史数据无法归因，遇到精确本人通知再清理。详见 [本人撤回放行](docs/own-recall-forwarding.md)。
- 仅用户反馈场景的0.80已经真机通过；**本轮新增设置、持久化与开关仍须真机验收**。源码/模拟器通过不等于实际TIM界面通过。

## 验收和反馈

私聊群聊各发三条同文消息，仅撤回中间一条。确认只有目标行标记；重开TIM返回聊天检查标记和时间。关闭当前聊天后对新增消息再撤回，确认TIM原行为恢复，同时其他聊天保持防撤回；重新开启后只对新事件生效。检查普通收发、滚动、前后台和账号切换。

有问题优先发设置页或目标消息截图，注明聊天类型、开关和是否重启。崩溃附`.ips`。不再反复查此前不存在的日志；若有新bootstrap可附数据沙盒Documents/TIMAntiRecall/TIMAntiRecall-bootstrap.log。诊断日志不带聊天内容；状态文件是有界身份元数据，勿作为普通日志公开分享。
